# Observability, Prometheus metrics, health probes, and W3C tracing hooks

We encapsulate Prometheus instrumentation (`prom-client` directly with per-container `Registry`) behind a narrow `MetricsPort` (`src/core/ports/metrics.ts`) implemented by `PromMetricsAdapter` and `NoopMetricsAdapter` in `src/infra/observability/`, serve `/`, `/health`, `/ready`, and `/metrics` from the `system` `Feature Module` (`src/modules/system/`), treat DB failures on `/ready` as `503 unhealthy` while treating Redis failures (when `REDIS_URL` is set) as `200 degraded` and omitting S3 storage probes, expose optional worker `/metrics` and `/health` via `WORKER_METRICS_PORT`, and correlate HTTP logs and background jobs with a zero-dependency W3C `traceparent` + `AsyncLocalStorage` hook feeding `createLogger`'s Pino `mixin()`.

## Considered Options

- **Use `@hono/prometheus` or `prom-client`'s global default registry directly in `Core` / `Feature Module`s**: Rejected because `@hono/prometheus` lacks clean route exclusions and SSE duration suppression (`streamSSE` resolves `await next()` at time-to-headers rather than stream close), using the global registry breaks parallel `createTestApp` Vitest suites with duplicate-metric errors, and importing `prom-client` outside `Infra` violates ADR-0001's `modules → core ← infra` layering.
- **Return `503` on Redis/Storage readiness errors or wrap `/ready` `503` in ADR-0002's `{ error }` envelope**: Rejected because ADR-0005 intentionally designed API caching and rate limiting to fail open on Redis blips (failing readiness on Redis would cascade into API downtime), periodic `HeadBucket` calls add external S3 traffic/latency to frequent probes, and returning `{ status, timestamp, checks }` consistently on both `200` and `503` lets orchestrators and operators inspect check state uniformly (an explicit probe exception to ADR-0002 alongside Better Auth).
- **Require a separate `/metrics` port, keep `src/worker.ts` portless, or parse Drizzle SQL for per-query histograms**: Rejected because `/metrics` on the main Hono app (optionally guarded by `METRICS_TOKEN`) matches ADR-0002/0005 while `WORKER_METRICS_PORT` lets separate worker processes be scraped in production without forcing a port locally, and parsing raw Drizzle SQL strings adds brittle cardinality overhead compared to HTTP duration + `/ready` DB latency.
- **Install `@opentelemetry/api` alone or `@hono/otel` + `BasicTracerProvider` upfront**: Rejected because `@opentelemetry/api` silently no-ops for root requests and `async`/`await` without registering `TracerProvider` and `AsyncLocalStorageContextManager`; a zero-dependency W3C `traceparent` + `AsyncLocalStorage` module in `src/core/observability/trace.ts` keeps the upgrade seam to `@hono/otel` isolated to one place.

## Consequences

- `src/env.ts` adds `METRICS_ENABLED` (default `true`, including `test`), optional `METRICS_TOKEN`, optional `WORKER_METRICS_PORT`, and `READINESS_TIMEOUT_MS` (default `2000`).
- `MetricsPort` (`recordHttpRequest`, `incSseConnection`, `decSseConnection`, `recordJob`, `recordCacheOp`, `recordRateLimit`, `render`) tracks HTTP (`http_requests_total`, `http_request_duration_seconds` via `hono/route` post-`next()`, `"__unmatched__"` on 404, excluding `/metrics`, `/health`, `/ready`, `/favicon.ico`, and omitting SSE `text/event-stream` durations), SSE (`sse_active_connections`, `sse_connections_total` without high-cardinality `topic` labels), Queue (`jobs_processed_total`, `job_duration_seconds`), Cache (`cache_operations_total`), RateLimit (`rate_limit_decisions_total`), and Node `collectDefaultMetrics()` (off when `NODE_ENV=test`).
- `src/modules/system/` documents `/`, `/health` (`{ status: "ok", timestamp }`), and `/ready` (`{ status: "ok" | "degraded" | "unhealthy", timestamp, checks: { db, redis } }`) in OpenAPI `/doc`, keeps `/metrics` off `/doc` (enforcing `Authorization: Bearer <METRICS_TOKEN>` when set and `404 NotFoundError` when `METRICS_ENABLED=false`), runs `/ready` probes via `Promise.allSettled` with cleaned-up timeouts and sanitized failure payloads (`{ status: "skipped" }` for Redis when `REDIS_URL` is unset), and `src/worker.ts` optionally exposes `/metrics` + `/health` (checking BullMQ `Worker` running state + Redis `ping()`) on `WORKER_METRICS_PORT`.
- `createApp` orders global middlewares as `requestId()` → `traceContext()` → `pinoLogger()` → `metricsMiddleware()` → `cors()` → `secureHeaders()` → `bodyLimit()` → `timeout()` → routes; malformed inbound `traceparent` headers silently fall back to minted IDs, HTTP response headers emit `X-Request-Id` only, and `getTraceContext()` / `formatTraceparent()` propagate trace IDs into Pino's `mixin()` and `QueuePort` jobs.
