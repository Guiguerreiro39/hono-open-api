# CI pipeline, multi-stage Dockerfile, and Docker Compose topology

We standardize container packaging on a single multi-stage `Dockerfile` built from `node:24-slim` (with Corepack `pnpm@10.19.0` and `"engines": { "node": ">=24" }`), `tsconfig.build.json` build isolation, non-root `node` execution, and exec-form `CMD ["node", "dist/src/index.js"]` so Node receives `SIGTERM` as PID 1 per ADR-0010; orchestrate the full runnable stack by default in `docker-compose.yml` (`redis`, `rustfs/rustfs` S3 + `amazon/aws-cli` `s3-init`, one-shot `migrate` init service gating `api` and `worker` over shared `db_data:/data`, plus `--profile observability` for Prometheus + Grafana); and gate PRs and default-branch pushes in `.github/workflows/ci.yml` across `verify` (including Drizzle migration drift), Compose-backed `integration`, and `docker build` smoke checks.

## Considered Options

- **Use `node:24-alpine`, build separate `api`/`worker` images, or bake `HEALTHCHECK` into `Dockerfile`**: Rejected because Debian `node:24-slim` glibc avoids musl DNS and native-addon edge cases (`libsql` provides gnu prebuilds), separate images duplicate runtime layers when one image serves `api`, `worker`, and `migrate` via `command` overrides, and moving `healthcheck`s to `docker-compose.yml` prevents `worker` from inheriting an API port check.
- **Default `docker compose up` to infra-only, use MinIO or SeaweedFS, or run migrations inside an `api` entrypoint wrapper**: Rejected because defaulting Compose to the full stack gives immediate out-of-the-box runtime verification (while `docker compose up redis s3 s3-init` still supports host `pnpm dev`), MinIO community Docker images were deprecated whereas RustFS provides straightforward env-driven S3 + web console setup (with `amazon/aws-cli` `s3-init` avoiding an app image build for infra-only startup), and a dedicated `migrate` init service honors ADR-0003's explicit CLI without multi-replica races.
- **Duplicate Redis/RustFS in GitHub Actions `services:` and ship a GHCR push workflow**: Rejected because running `docker compose up -d --wait redis s3 s3-init` in CI `integration` verifies the actual Compose wiring without maintaining parallel S3/bucket definitions, and registry release workflows are left to starter adopters.

## Consequences

- `package.json` pins `"packageManager": "pnpm@10.19.0"` and `"engines": { "node": ">=24" }`; `.dockerignore` excludes `.git`, `node_modules`, `dist`, `.env*`, `*.db`, `tests`, `docs`, `coverage`, and `.storage`; `Dockerfile` chains `base` → `deps` → `build` (`pnpm build`) → `prod-deps` → `runtime` (`USER node`, pre-created `node:node`-owned `/data`, copying `dist/`, `src/infra/db/migrations/`, and `package.json`).
- `docker-compose.yml` runs `api` (`PORT=9999`) and `worker` (`command: ["node", "dist/src/worker.js"]`, `WORKER_METRICS_PORT=9091`) under `NODE_ENV=production` with clearly commented dev-only `${VAR:-...}` fallbacks, `S3_ENDPOINT=http://s3:9000`, `S3_PUBLIC_ENDPOINT=http://localhost:9000`, `S3_FORCE_PATH_STYLE=true`, per-service `/health` checks, `stop_grace_period: 15s` (exceeding ADR-0010's `10000ms` timeouts), and `depends_on` (`migrate` and `s3-init` `service_completed_successfully`, `redis` `service_healthy`).
- `src/infra/db/client.ts` enables SQLite `PRAGMA journal_mode = WAL` and `PRAGMA busy_timeout = 5000` on `file:` URLs so `api` and `worker` safely share `db_data:/data/app.db`; `--profile observability` starts `prom/prometheus` (`docker/prometheus/prometheus.yml` scraping `api:9999` and `worker:9091` with `METRICS_TOKEN` unset in Compose) and `grafana/grafana` (`docker/grafana/provisioning/` Prometheus datasource only).
- `.github/workflows/ci.yml` runs on `push` (default branch) and `pull_request` (with concurrency cancel on non-default-branch runs) using Node `24` + `pnpm@10.19.0`: `verify` (`pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`, and `pnpm db:generate` + `git diff --exit-code src/infra/db/migrations`), `integration` (`docker compose up -d --wait redis s3 s3-init` + `pnpm test:integration` with `always()` teardown), and `docker` (`docker build` smoke test without registry push).
