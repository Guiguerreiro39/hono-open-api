# Object storage adapter, upload flows, and files module

We encapsulate blob storage behind a `Core` `StoragePort` (`src/core/ports/storage.ts`) implemented in `src/infra/storage/` by `MemoryStorageAdapter` (`test`), `LocalStorageAdapter` (`development`), and `S3StorageAdapter` (`@aws-sdk/client-s3` + `@aws-sdk/s3-request-presigner` + `@aws-sdk/lib-storage`, required in `production` unless `STORAGE_DRIVER=local`), implement `src/modules/files/` with both server-proxied multipart (`POST /api/v1/files`) and presigned direct uploads (`POST /api/v1/files/presign` → `PUT` → `POST /api/v1/files/{id}/complete`) backed by HMAC-signed `/_storage/*` dev/test parity, keep all files private and owner-scoped per ADR-0004, stream downloads via `GET /api/v1/files/{id}/download` alongside `GET /api/v1/files/{id}/url`, and handle DB-first hard deletion with `QueuePort` object cleanup retries and hourly `files.prunePending` pruning.

## Considered Options

- **Support only multipart proxy uploads or only presigned direct uploads**: Rejected because multipart-only buffers large uploads through Node.js in production, whereas presigned-only breaks zero-CORS Scalar `/reference` and simple CLI DX and requires client-side multi-step handshakes for small files.
- **Name the port `ObjectStorage`, redirect `302` by default on `/download`, or add a `visibility: "public"` toggle**: Rejected because `StoragePort` aligns with `GLOSSARY.md` and `AuthPort`/`CachePort`/`QueuePort` naming, `302` redirects trigger CORS/Authorization failures for Bearer `fetch()` clients and break when S3 runs on internal Docker DNS (`S3_ENDPOINT`), and public unauthenticated routes bypass ADR-0004's RBAC baseline.
- **Allow `image/svg+xml` / trust client `Content-Type`, or skip signed-URL parity on local/memory adapters**: Rejected because trusting MIME headers or serving SVG/HTML enables stored XSS without sanitization, while omitting local signed transfer routes breaks end-to-end presigned upload/download testing without an S3 container.

## Consequences

- `src/env.ts` adds `STORAGE_DRIVER` (`"memory" | "local" | "s3"`, auto-selecting `"memory"` in `test`, `"s3"` in `production`, and `"s3"` in `development` when `S3_BUCKET` is set else `"local"`), `STORAGE_LOCAL_DIR` (`"./.storage"`), `STORAGE_MAX_FILE_SIZE_BYTES` (`10485760`), `STORAGE_PRESIGN_MAX_FILE_SIZE_BYTES` (`104857600`), `STORAGE_PRESIGN_EXPIRES_SECONDS` (`900`), `STORAGE_SIGNING_SECRET` (optional fallback to `BETTER_AUTH_SECRET`), `S3_BUCKET`, `S3_REGION` (`"us-east-1"`), `S3_ENDPOINT`, `S3_PUBLIC_ENDPOINT`, `S3_ACCESS_KEY_ID` + `S3_SECRET_ACCESS_KEY` (optional as a pair to allow IAM/IRSA default credential chains), and `S3_FORCE_PATH_STYLE` (`false`).
- `StoragePort` exposes `put`, `get(key, { range? })` (returning `null` on missing), `head` (returning `null` on missing), `delete` (idempotent), `getSignedPutUrl`, `getSignedGetUrl`, and optional `handleSignedRequest?(req)`. `S3StorageAdapter` configures `requestChecksumCalculation: "WHEN_REQUIRED"` and `responseChecksumValidation: "WHEN_REQUIRED"` (avoiding AWS SDK v3 `>= 3.729.0` R2/MinIO/browser presign failures) and rewrites presigned origins to `S3_PUBLIC_ENDPOINT` when set; `LocalStorageAdapter` uses atomic temp-file + `rename` writes and `path.resolve` containment guards, and both local/memory adapters share `app.on(["PUT", "GET"], "/_storage/*", ...)` HMAC-SHA256 transfer parity (`404` under S3).
- `src/infra/db/schema/files.ts` stores `id` (UUIDv4 PK), `userId` (FK `user.id`, `onDelete: "cascade"`), `key` (unique server-generated `files/<userId>/<id>`), `originalName` (sanitized basename), `mimeType`, `sizeBytes`, `checksumSha256` (nullable), `status` (`"pending" | "ready"`), `expiresAt` (`timestamp_ms` nullable), `createdAt`, and `updatedAt`. `GET /api/v1/files` defaults to `status = "ready"` (`?scope=all`/`?userId=` via `file:read:any`, `404` on foreign IDs per ADR-0004).
- Uploads validate against a safe default MIME allowlist (`image/jpeg`, `image/png`, `image/webp`, `image/gif`, `application/pdf`, `text/plain`, `text/csv`, `application/json` — excluding SVG/HTML) and verify binary magic bytes (directly on multipart `POST /api/v1/files` or via 4096-byte `range` read on `POST /api/v1/files/{id}/complete`, deleting mismatched objects and returning `422 ValidationError`). Downloads stream with `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`, and `409 ConflictError` if `status === "pending"` (with `/complete` idempotent `200` once `ready` and `409` if expired or absent in storage).
- `POST /api/v1/files` and `POST /api/v1/files/presign` use ADR-0005's `10 req/min` upload rate limit; `POST /api/v1/files` replaces the 1 MB global `bodyLimit` with `STORAGE_MAX_FILE_SIZE_BYTES + 64 KB`; `POST /api/v1/files`, `GET /api/v1/files/{id}/download`, and `/_storage/*` bypass ADR-0002's `30s` `timeout()`; `src/modules/files/files.jobs.ts` defines `files.deleteObject` (enqueued via `QueuePort` on transient storage failures after DB-first `DELETE` or failed multipart cleanup) and hourly `files.prunePending` (`"0 * * * *"`) removing expired `pending` rows and objects.
